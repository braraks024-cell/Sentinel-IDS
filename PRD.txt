------------------------------------------------------------------------------
1. PRODUCT OVERVIEW
------------------------------------------------------------------------------
Product Name : Deep Learning-Based Network Intrusion Detection System (IDS)

Summary:
A web application that lets a user upload network traffic data (CSV) or enter
traffic features manually, and uses a trained Artificial Neural Network (ANN)
to classify traffic as Normal or Malicious (and, where the dataset allows, as
DoS, Probe, R2L or U2R). Results are shown on a cybersecurity-style dashboard
with charts, confidence scores, history and downloadable reports. The ANN is
compared with Random Forest and Logistic Regression.

One-line pitch:
"Upload traffic, get instant AI-powered attack detection with transparent,
honestly-evaluated results."

------------------------------------------------------------------------------
2. PROBLEM STATEMENT
------------------------------------------------------------------------------
Networks face continuous threats (DoS, scanning, unauthorized access).
Signature-based IDS tools miss new or modified attacks and are hard for
students to understand. Students need a practical, explainable project that
shows how deep learning can learn patterns of malicious traffic from labeled
data, with real evaluation instead of claimed accuracy.

------------------------------------------------------------------------------
3. GOALS AND NON-GOALS
------------------------------------------------------------------------------
Goals
  G1. Build a working end-to-end IDS using a real public dataset.
  G2. Train, evaluate, save and reload an ANN; compare with RF and LR.
  G3. Provide an intuitive dashboard, prediction, history and reports.
  G4. Demonstrate good practice: preprocessing, validation, secure auth.
  G5. Be clear, honest and easy to explain in a viva/demo.

Non-Goals (v1.0)
  - Live packet capture or real-time network monitoring.
  - Automatically blocking traffic or acting as a firewall.
  - Generating or simulating attacks.
  - Production-scale deployment, multi-tenant cloud hosting.
  - Guaranteeing detection on modern/unseen traffic.

7. FUNCTIONAL REQUIREMENTS (PRODUCT VIEW)
------------------------------------------------------------------------------
7.1 Authentication
    Secure register/login/logout, password hashing, protected routes.

7.2 Upload and Analysis
    CSV only, size limit, column validation, same preprocessing as training,
    per-record label + confidence, summary counts.

7.3 Manual Prediction
    Form for key features (duration, protocol_type, service, flag, src_bytes,
    dst_bytes, count, serror_rate, etc.), instant result via AJAX, input
    validation.

7.4 Model Training (train_model.py)
    Load -> clean -> encode -> scale -> split -> train ANN/RF/LR -> evaluate
    on test set -> save model, scaler, encoder, metrics.json and plots.

7.5 Evaluation Page
    Accuracy, precision, recall, F1 for each model; confusion matrix; ANN
    training/validation loss and accuracy curves; comparison chart. All values
    come from saved real results; if absent, show "Model not trained yet".

7.6 Dashboard
    Cards: total records, normal, attacks, attack rate. Charts: attack
    distribution (doughnut), traffic over time (bar/line). Recent alerts list.

7.7 History and Reports
    Store analyses and predictions; list with timestamp, type, counts,
    confidence; export CSV.

------------------------------------------------------------------------------
  Performance : manual prediction < 2 s; 10k-row CSV < 30 s.
  Usability   : intuitive navigation, clear error messages, mobile responsive.
  Reliability : graceful handling of bad input and missing model files.

                execution of uploads, user data isolation.
  Maintainability : modular folders, comments, config file.
  Portability : runs locally on Windows/Linux/macOS via VS Code.
  Honesty     : no fabricated metrics; limitations disclosed.

10. DATA AND MODEL REQUIREMENTS
------------------------------------------------------------------------------
Dataset   : NSL-KDD (primary) or CIC-IDS2017 (alternative, sampled).
            README must include download links and placement steps.
Preprocessing : missing values, categorical encoding, normalization,
            stratified train/test split.
ANN       : Input -> Dense(128, ReLU) -> Dropout -> Dense(64, ReLU) -> Dropout
            -> Dense(32, ReLU) -> Output (Sigmoid / Softmax).
Baselines : Random Forest, Logistic Regression.
Metrics   : accuracy, precision, recall, F1, confusion matrix.
Persistence : save/reload model and preprocessing objects.
Disclaimer : predictions reflect the training data and can be wrong.

12. RISKS AND MITIGATIONS
------------------------------------------------------------------------------
R1  Dataset is dated (NSL-KDD).        -> State limitation; mention CIC-IDS2017
                                          as future work.
R2  Class imbalance (R2L, U2R rare).   -> Class weights / report per-class
                                          metrics / explain lower recall.
R3  Upload schema mismatch.            -> Strict column validation and a
                                          downloadable sample CSV template.
R4  Overfitting.                       -> Dropout, early stopping, validation
                                          split, unseen test set.
R5  TensorFlow install issues.         -> Pin Python 3.9-3.11, pin versions in
                                          requirements.txt, give fixes in README.
R6  Long training time.                -> Use NSL-KDD, early stopping, optional
                                          data subsampling.
R7  Security flaws in uploads.         -> Extension/size checks, secure_filename,
                                          never execute files.
